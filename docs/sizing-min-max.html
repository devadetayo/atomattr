Min and max size

Constrain element dimensions with min and max attributes.

When to use it

Constrain element dimensions with min and max attributes. Use this page when you are deciding which attribute belongs on an element and what kind of value that attribute expects. The examples start small on purpose, then build toward patterns you are likely to repeat in real interfaces.

A helpful way to read Atomattr is to scan the element from left to right: layout first, then spacing, then color, then typography, then interaction. You do not have to follow that order perfectly, but keeping related attributes near each other makes a component easier for the next person to understand.

basic.html 
<section min-h="screen" max-w="5xl" mx="auto">...</section>

More examples

These examples show the same attribute family in practical situations. Copy the closest pattern first, then swap the values for your design system.

Reading the syntax

Use the base attribute for the default style. Add breakpoint prefixes for layout changes, state prefixes for interaction, and dark- prefixes when a theme needs a different value. This keeps the full behavior of the element visible without sending the reader into a second file.

If an attribute maps to a CSS property, the value usually follows that property. When Atomattr has a scale for the property, short tokens such as 4, xl, muted, or primary/80 make the common cases fast. When a design needs precision, raw CSS values are still valid.

combined-pattern.html 
<article display="flex" flex-col gap="3" p="5" rounded="xl" border="border" min-w="4" md-min-w="6">
  <h3 font-size="lg" font-weight="bold">Min and max size pattern</h3>
  <p text="muted" line-height="relaxed">
    Combine the attribute with layout, spacing, and color so the whole component remains readable.
  </p>
  <button max-w="4" hover-max-w="4" px="4" py="2" rounded="lg">
    Continue
  </button>
</article>

Practice patterns

The fastest way to learn this page is to copy one example, paste it into the playground, and change one attribute at a time. Keep the structure stable while you experiment with values. Once the result feels right, move the same attributes into your real component.

When a component starts to feel noisy, group the attributes mentally by purpose: layout, spacing, color, type, border, effects, and state. Atomattr does not require a special order, but a consistent order makes examples easier to teach and production markup easier to review.

min-and-max-size-practice.html 
<section display="grid" gap="4" p="6" bg="gray-50" dark-bg="gray-950">
  <article bg="white" dark-bg="gray-900" rounded="2xl" border="border" p="5">
    <h3 font-size="xl" font-weight="bold">Min and Max Size</h3>
    <p mt="2" text="muted" line-height="relaxed">
      Use this as a small playground for the ideas on this page.
    </p>
    <button mt="4" bg="primary" text="white" hover-bg="primary/80" px="4" py="2" rounded="lg">
      Try it
    </button>
  </article>
</section>
