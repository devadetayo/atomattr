Markup that actually reads like the interface.

Styling is a property of an element, so it belongs on the element. No sprawling class strings, and no stylesheet to cross-reference.

button.html 
<button bg="primary"
  hover-bg="primary/80"
  text="white"
  px="6" py="3"
  rounded="full">
  Get started
</button>

Attribute-first

One attribute for every decision.

There is exactly one place a style decision lives: the attribute. Not a class, not a modifier, not a wrapper component. Just bg=, px= and rounded=, spelled the way you would say them out loud.

Read the docs

ATOMATTR VS TAILWIND

Same decisions. A different shape.

Tailwind is a great utility system, and Atomattr borrows its vocabulary. The difference is where the decisions live: one long class string, or one attribute per decision.

Tailwind class="…" 
<button
  class="inline-flex items-center gap-2
    rounded-full bg-indigo-600 px-6 py-3
    text-sm font-semibold text-white
    shadow-lg hover:bg-indigo-500
    focus-visible:outline-2
    md:px-8 md:text-base
    dark:bg-white dark:text-gray-950
    dark:hover:bg-gray-200">
  Get started
</button>
Atomattr attr="…" 
<button
  display="inline-flex" items="center" gap="2"
  rounded="full"
  bg="primary" hover-bg="primary/80"
  dark-bg="#fff" dark-text="gray-950"
  text="white"
  px="6" md-px="8" py="3"
  font-size="sm" md-font-size="md"
  font-weight="600" shadow="lg">
  Get started
</button>

Scannable

Each decision is its own name and value, so you can read down a column instead of parsing a string.

Variants stay beside values

px and md-px sit next to each other, rather than px-6 and md:px-8 scattered through the string.

Semantic tokens

Say primary, muted or border and let the theme decide the actual color.

React Native, same words

The vocabulary carries over to <View>, so web and mobile share one way of styling.
