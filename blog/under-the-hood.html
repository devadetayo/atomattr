Under the Hood: The Engine

A tour of the parser, the generator and the observer, in the order a single attribute travels through them.

DdevadetayoAtomattr

The engine has three jobs: find attributes, understand them, and write CSS. Each job lives in its own file in the package source, so we can follow a single attribute, md-hover-bg="blue-700", from the DOM to the stylesheet.

1. The observer

engine.js starts with an initial pass: for every element it loops over the attributes and skips any that are known not to be styles (such as id or href). Then it attaches a MutationObserver to the document element, watching attribute changes, added nodes and the whole subtree. Elements that arrive later get the same treatment, and so do attributes you change.

2. The parser

parser.js receives the name and value and works out what they mean:

  • It checks for a before- or after- prefix, which targets a pseudo-element.
  • It finds the property by matching the longest known key at the end of the name, so grid-cols wins over cols-like shorter matches.
  • Whatever remains in front is a list of modifiers, consumed one by one: dark, group-hover, a breakpoint (sm to 2xl) or a state (hover, focus, active, disabled and others).
  • If any leftover text is not a known modifier, the attribute is not ours and is ignored.

For our example, bg is the property, md becomes a media-query wrapper and hover becomes a pseudo-class. The result is a selector built directly from the attribute:

css
@media (min-width: 768px) {
  [md-hover-bg="blue-700"]:hover { background-color: … }
}

3. The generator

generator.js turns the value into real CSS. It resolves color names and the /alpha shorthand (so primary/50 becomes a color-mix against transparent), spacing and size scales, font sizes, shadows and raw values such as 320px or linear-gradient(…).

Some properties compose. Transforms (scale, rotate, translate-x and friends) and filters (blur, brightness…) each write a CSS variable, and the final transform or filter declaration combines all of those variables. That is why scale="1.1" rotate="3deg" works together on one element.

4. The injection

Finished rules go into a single <style id="atomattr-generated"> element through sheet.insertRule. A cache keyed by attribute name and value means a hundred elements using p="4" cause exactly one rule. A rule the browser rejects is cached too, so it is not retried on every pass.

Why this mattersRules are generated per distinct attribute and value, not per element. The stylesheet grows with the variety of your design, not with the size of your page.

Control from your own code

The package exports startAtomAttr, stopAtomAttr, refreshAtomAttr(root) and clearGeneratedRules. In the browser it starts automatically on import; call refreshAtomAttr when you want to force a pass over a subtree, for example after writing into a shadow root or a detached container.
