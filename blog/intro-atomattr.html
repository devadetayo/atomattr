Introducing AtomAttr: The Runtime CSS Revolution

Why styling lives on the element as attributes, and how the engine turns them into CSS right in the browser.

DdevadetayoAtomattr

Most styling systems ask you to write a name on the element and then describe that name somewhere else: a class in a stylesheet, a token in a config, a component in a library. Atomattr removes the second step. The description is the attribute.

html
<button bg="primary" text="white" px="4" py="2" rounded="lg" hover-bg="blue-700">
  Launch
</button>

There is no stylesheet to open for that button. A small engine reads the attributes, turns each one into a CSS rule, and injects the rule into the page. Change an attribute and the style follows.

Why attributes?

Attributes are already how HTML carries state: disabled, aria-expanded, data-*. Putting presentation there too has a few practical effects:

  • One place to look. What an element is and how it looks sit in the same tag.
  • No naming. There is no .card-inner-wrapper to invent, search for, or leave behind when the markup changes.
  • Readable diffs. A styling change shows up on the line of the element it changes.
  • Plain structure. Values like px="4" or bg="primary" read like a sentence, with the property name first.

How it works in one paragraph

When the page loads, the engine walks every element, reads each attribute name and value, and asks a parser whether it describes a style. If it does, a generator builds a CSS rule such as [px="4"] { padding-left: … } and inserts it into a single <style id="atomattr-generated"> tag. A MutationObserver keeps watching, so elements added later, or attributes changed later, are styled too. The full walk-through is in Under the Hood.

Getting started

Add the defaults stylesheet and the script, then write attributes. That is the whole setup:

html
<link rel="stylesheet" href="dist/defaults.css" />
<script src="dist/atomattr.min.js" defer></script>

<div p="6" rounded="2xl" bg="surface" border="1px solid border">
  Hello, attributes.
</div>
Live result

The same attribute vocabulary is available in React and React Native, so what you learn on the web carries over. Responsive and state variants are prefixes on the same attribute: md-px="8", hover-bg="blue-700", dark-bg="gray-950".
