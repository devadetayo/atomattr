How to share what you build with Atomattr, and what makes a submission easy to feature.

DdevadetayoAtomattr

The best way to see what a styling system can do is to look at what people make with it. This post is an open call: if you build something with Atomattr, we would like to see it, and this is how to share it so it is easy to feature.

What we are looking for

  • Components you would reuse: buttons, cards, forms, navbars, empty states.
  • Full pages and templates: landing pages, dashboards, docs.
  • Experiments that push the attribute vocabulary: motion, gradients, unusual layouts.
  • Write-ups of what worked and what did not, including the rough edges.

How to share

  • Build it in the Studio or write it by hand with Atomattr attributes.
  • Read the contribution guide for the current submission steps.
  • Share a link or snippet on Discord, or open an issue or pull request on GitHub.

What makes a submission easy to feature

  • A single self-contained snippet that runs when pasted into an empty page.
  • Attributes only, no extra stylesheet, so it demonstrates the framework itself.
  • Both light and dark mode checked.
  • A one-line description and your name or handle for credit.

Browse what is already here

Atomattr UI collects published components in a gallery where you can preview each one and copy its code. It is a good model for the sort of thing a submission can look like.
